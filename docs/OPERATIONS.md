# 운영 가이드 (소유자용, ROADMAP P6)

> 요약: 소유자가 할 일은 Binance 키를 넣고, 텔레그램으로 봇을 페어링하고, 하루 한 번 일일 리포트를 읽는 것뿐입니다. 나머지(종목 선정, 신호, 주문, 손절, 리서치, 발굴, 챌린저 승격, 킬 스위치)는 모두 자동입니다. **지금 출하 기본값은 켜진 알파가 0개라 봇은 거래하지 않고 학습만 합니다.** "왜 거래했나 / 왜 안 했나"는 텔레그램 `/why <심볼>`, 알파별 상태는 `/alphas`, 학습 루프 전체는 웹 대시보드의 **연구·학습** 페이지(`/research`)에서 봅니다. 수익이 검증된 봇이 아닙니다. 실거래하지 마세요.

## 1. 시작하기

| 단계 | 할 일 | 참고 |
|---|---|---|
| 1. 실행 | Docker: `cp .env.example .env` → `docker compose up -d --build`. 로컬: `pip install -e .` → `heartless run` | 기본 PAPER 모드. 키 없이도 실시간 시세로 동작 |
| 2. 텔레그램 | BotFather에서 봇 토큰을 받아 `.env`의 `TELEGRAM_BOT_TOKEN`에 넣거나 웹 설정 화면에서 저장 → 재시작 | |
| 3. 페어링 | 로그의 `TELEGRAM PAIRING CODE: …`를 봇에게 개인 채팅으로 `/start <코드>` | 코드는 시작마다 새로 생기고 10분 또는 5회 실패 뒤 만료. `TELEGRAM_OWNER_ID`를 지정하면 페어링이 필요 없음(권장) |
| 4. Binance 키 | 웹 설정 카드(HTTPS 또는 로컬 접속) 또는 `/setkeys 키 시크릿` (메시지는 즉시 삭제) | 선물 거래 권한만, 출금 권한 없이, 가능하면 IP 제한. `data/secrets.json`(0600)에 저장 |
| 5. 웹 대시보드 | `/web`으로 받은 주소로 접속 | 토큰은 첫 접속 때 HttpOnly 쿠키로 옮겨지고 주소창에서 사라짐 |

- 웹은 기본으로 루프백(127.0.0.1:8080)에만 열립니다. 밖에서 보려면 HTTPS 리버스 프록시, VPN, SSH 터널(`ssh -L 8080:127.0.0.1:8080 서버`) 중 하나를 쓰세요.
- `heartless doctor`로 키·연결·권한을 점검할 수 있습니다.

## 2. 지금 봇이 하는 일

- **챔피언**(paper 엔진)이 현재 파라미터로 실시간 페이퍼 거래를 합니다. 챔피언에 켜진 알파가 없으면 신호를 평가하지 않으므로 거래도 없습니다.
- **리서치 사이클**(6시간마다, 별도 프로세스)이 최근 120일로 모든 알파를 워크포워드 평가하고, 나아진 후보를 **챌린저**로 투입합니다.
- **알파 발굴**(매일)이 규칙 수만 개를 검사해, 다중검정과 검증 구간을 통과한 규칙만 `discovered` 챌린저로 투입합니다.
- **챌린저**(최대 2개)는 실시간 페이퍼로 거래하고, 시작 후 **14·30·60·90일 판정점**(표본 외 판정에서 탈락한 알파를 켜는 챌린저는 30·60·90일)에서만 승격을 판정합니다. 승격되면 그 변경분이 챔피언에 들어가고, 그때부터 챔피언이 그 알파로 거래합니다.
- **킬 스위치**는 챔피언의 켜진 알파가 운영 거래에서 계속 지면(CUSUM -8σ 또는 최근 30건 합 < -20R) 즉시 끕니다. 다시 켜는 길은 챌린저 승격뿐입니다.
- 판정 기준과 이유: `docs/SELF_IMPROVEMENT.md`. 알파별 표본 외 판정: `docs/OOS_2022_2024.md`, `docs/RESEARCH_P2.md`, 증거 기록 `heartless/strategy/evidence.json`.

### 4.1 `/why <심볼>`

포지션이 있으면 진입 근거 전체를 보여줍니다.

```
🔎 ETHUSDT 왜 들고 있나 — 🧪 PAPER · 🟢 LONG [OPEN]
알파 htf_trend · 1h · 레짐 RANGE · 앙상블 점수 0.72
근거: htf_trend 1주 추세 +2.1σ, 2일 조정
태그: z_week=2.13, z_pull=-1.2
진입 201.22 → 현재 201.17 · 보유 0s
손절 195.15 · 목표 213.26
리스크 50.24 USDT (1R = 6.07) · 지금 -0.01R (미실현 -0.33 USDT) · 기대 +2.0R
증거: P1 OOS 탈락: 2022~2024 n=2064 -0.042R t -1.07, 양수 연도 1/3, 스트레스 -0.057R
운영 6건 평균 +0.40R t +1.02 (paper) · 킬 스위치 CUSUM +0.00/-8σ, 최근 0건 합 +0.0/-20R
```

- **근거·태그**: 알파가 신호를 낼 때 남긴 설명과 피처 값입니다.
- **손절**: 본절 이동·트레일링으로 바뀌었으면 최초 손절과 "지금 손절 시 +xR"이 함께 나옵니다.
- **리스크 / 지금 / 기대**: 진입 때 건 위험액(1R), 현재가 기준 R, 목표가(없으면 앙상블 기본 1.5R) 기준 기대 R입니다.
- **증거**: 그 알파가 마지막으로 받은 사전 등록 시험(P1 OOS, P2 VALID, 2025 확인 시험)의 판정과 수치입니다. `t +3.21/3`은 "일 단위 t 3.21, 기준 3"입니다.
- **운영**: 이 엔진에서 그 알파의 전체 거래 기록. 킬 스위치 수치는 그 알파를 켠 뒤의 거래만 셉니다.

포지션이 없으면 최근 판단과 지금 진입을 막는 이유를 보여줍니다.

```
🔎 BTCUSDT — 🧪 PAPER 포지션 없음
⚠️ 챔피언에 켜진 알파가 없어(0개) 챔피언은 신호를 평가하지 않습니다. 켜는 길은 챌린저 승격뿐입니다 (/alphas)
진입 차단: 손실 뒤 종목 쿨다운 ~14:20
🛑 킬 스위치로 꺼진 알파 intraday_levels (10-09, vkill1)
최근 판단 (신호가 있었던 봉, 최신순)
• 10-12 08:00 challenger-1 [RANGE] 신호 trend_pullback LONG 0.20 → 앙상블 점수 임계값 0.5 미달
```

거절 사유는 다음 중 하나입니다.

| 단계 | 사유 |
|---|---|
| 앙상블 | 점수 임계값(기본 0.50) 미달, 또는 반대 방향 신호와 충돌 |
| 리스크 | 일시정지, 손실 한도로 진입 중단, BTC 급변 뒤 진입 중단, 손실 뒤 종목 쿨다운, 동시 포지션 한도, 같은 방향 한도, 총 레버리지 한도 |
| 체결 | 스프레드 과다(12bp 초과), 메타 모델 거부, 주문 수량 0, 손절가가 이미 현재가를 넘음, 주문 미접수 |
| 진입 | 시장가/지정가 주문 접수 |

- 판단 기록은 **메모리에만** 종목·엔진별 최근 5건을 둡니다. 재시작하면 비어 있습니다.
- 신호가 하나도 없던 봉은 기록하지 않습니다. 대부분의 알파는 1시간·4시간·일봉 마감에만 평가합니다.
- 챌린저의 판단도 함께 나옵니다(챔피언에 알파가 없어도 챌린저는 자기 알파로 평가합니다).

### 4.2 `/alphas`

알파마다 한 줄입니다. ✅ 챔피언에서 켜짐, 🧪 챌린저가 켜거나·조정하거나·거래 중, ⛔ 꺼짐.

```
✅ htf_trend · P1 OOS 탈락: 2022~2024 n=2064 -0.042R t -1.07, … · 운영 6건 평균 +0.40R t +1.02 · 킬 스위치 CUSUM +0.00/-8σ, 최근 0건 합 +0.0/-20R · 신뢰 1.00 · 챌린저 challenger-1(거래)
🧪 trend_pullback · P1 OOS 탈락: … · 운영 0건 · 챌린저 challenger-1(켬)
⛔ vol_breakout_dbox · P2 VALID 탈락: TRAIN 2022~2024 n=1148 +0.128R t +3.21/3 · VALID 2026 n=311 +0.101R t +0.82/1 · 운영 0건
⛔ intraday_levels · P1 OOS 탈락: … · 운영 0건 · 🛑 킬 스위치로 꺼짐 (vkill1, CUSUM <= -8sd)
```

- **증거 단계**: `P1 OOS`(2022~2024 한 번 판정), `P2 VALID`(TRAIN 관문 → 2026 VALID), `2025 확인 시험`(봉인 2025 단일 후보 시험). `OOS 미검증`은 판정을 받은 적이 없거나, 판정 뒤 파라미터 설계가 바뀐 경우입니다.
- **운영**: 주 엔진에서 그 알파의 전체 거래(n, 평균R, 일 단위 t).
- **챌린저 역할**: 켬(그 알파를 켜는 변경), 끔, 조정(파라미터 변경), 거래(기준 챔피언에서 물려받아 거래).
- 켜진 알파가 없으면 끝에 "활성 알파 없음"과 거래 시작 조건, OOS 판정 요약, 킬 스위치 설정이 붙습니다.

- 연구·학습 페이지는 서버에서 그려 보내며 스크립트를 실행하지 않습니다. 외부 리소스(CDN, 웹폰트, 외부 이미지)를 쓰지 않고, 콘텐츠 보안 정책으로도 막습니다. 새로 보려면 새로고침하세요.
- 봉인 원장은 저장소의 `docs/results/seal_ledger.jsonl`을 읽습니다. Docker 이미지에는 `docs/`가 들어가지 않으므로 컨테이너에서는 "원장 기록 없음"으로 나옵니다.
- 모든 화면은 소유자 토큰이 있어야 열립니다. 토큰 없이 열면 로그인 화면(401)이 나오고, 틀린 토큰을 반복하면 그 IP를 15분 동안 막습니다.

## 6. 알림과 대응

| 알림 | 뜻 | 할 일 |
|---|---|---|
| 포지션 진입 / 종료 / 1차 익절 | 거래 발생 | 궁금하면 `/why <심볼>` |
| ⚠️ 리스크: 일일 손실 한도 | 하루 -3%: 다음 자정까지 신규 진입 중단 | 없음(자동 해제) |
| ⚠️ 리스크: 고점 대비 낙폭 | -15%: 봇 일시정지 | 원인을 확인한 뒤 `/resume` |
| 🛑 알파 킬 스위치 | 알파가 운영에서 계속 짐 → 그 알파를 끈 새 챔피언 | 없음. 다시 켜는 것은 챌린저 승격만 가능 |
| 🏆 파라미터 승격 | 챌린저가 판정점 기준을 넘어 챔피언에 반영 | `/alphas`, 연구·학습 페이지에서 확인 |
| 챌린저 종료 | 조기 탈락, 열위, 시험 기간 종료, 킬 스위치 | 없음(같은 변경은 90일 동안 재시험 안 함) |
| ❗ 오류 | 주문·리서치·연결 오류(10분에 5건까지) | 반복되면 로그 확인 |
| 🎓 페이퍼 졸업 기준 충족 | 14일 60건 이상, PF 1.25 이상, MDD 8% 이하, 순익 + | 8절을 읽고 판단 |

## 7. 비상 조치

- **신규 진입만 멈추기**: `/pause` (재시작해도 유지). 다시 시작은 `/resume`.
- **특정 종목 청산**: `/close BTCUSDT` 또는 포지션 메시지의 즉시 청산 버튼.
- **전부 멈추기**: `/kill` → 전량 시장가 청산 + 신규 진입 정지. 웹 "전량 청산"도 같습니다.
- **실거래에서 빠지기**: `/mode paper` → 라이브 포지션을 모두 청산한 뒤 페이퍼로 전환.
- 봇 프로세스를 끄면(SIGTERM, Ctrl+C) 리서치 작업자도 함께 끝납니다. **실거래 포지션의 거래소 손절 주문은 거래소에 남아** 봇이 꺼져 있어도 보호됩니다. 다시 켜면 거래소와 포지션·주문을 맞춘 뒤 이어서 관리합니다.

## 8. 실거래 전환 (권하지 않음)

- 지금까지 어떤 알파도 사전 등록 시험을 통과하지 못했습니다. 실거래를 권하지 않습니다.
- 전환은 언제나 소유자의 확인으로만 일어납니다(`/golive`, `/mode live`, 졸업 알림 버튼, 웹 "LIVE 전환"). 졸업 기준을 채우지 못했으면 경고가 함께 나옵니다.
- 실거래 중에도 페이퍼 챔피언과 챌린저는 계속 돌며 학습합니다. 계정은 단방향·격리마진으로 쓰고, 같은 계정의 수동 포지션은 봇이 인수해 보호 손절을 겁니다.

## 10. 문제 해결

| 증상 | 확인 |
|---|---|
| 텔레그램이 응답하지 않음 | 토큰, 소유자 ID(`TELEGRAM_OWNER_ID`), 페어링 만료 여부(로그). 다른 계정에서 보낸 명령은 무시됩니다 |
| `/status`에 "스트림 끊김" | 네트워크. 자동 재연결되며, 빈 구간은 REST로 채웁니다 |
| 리서치 실패가 반복됨 | `/status`의 마지막 오류, 메모리(한 사이클 약 1.6GB), 디스크 |
| 대시보드 401 | 토큰이 바뀌었으면 `/web`으로 새 주소를 받으세요 |
| 대시보드 429 | 틀린 토큰을 10번 넘게 보냄. 15분 뒤 다시 |
| 거래가 전혀 없음 | 정상일 가능성이 큽니다. `/alphas`에서 켜진 알파 수, `/why <심볼>`에서 거절 사유를 보세요 |

## 11. 보안

- 텔레그램 봇 토큰, 대시보드 토큰, Binance 키가 다른 곳에 노출되면 즉시 재발급하세요(BotFather `/revoke`, Binance 키 삭제 후 재등록).
- `/web` 응답과 시작 메시지에는 대시보드 토큰이 들어 있습니다. 소유자 개인 채팅에서만 보내며, 그 대화를 공유하지 마세요.
- `/why`, `/alphas`, 일일 리포트, 연구·학습 페이지와 `/api/learning`은 키·토큰을 담지 않습니다(테스트로 확인).
