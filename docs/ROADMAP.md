# Heartless 로드맵 (2026-10-10 수립)

이 문서는 남은 작업 전체의 계획이자 **사전 등록(pre-registration)** 문서입니다. 판정 기준은 데이터를 보기 전에 이 문서로 고정합니다. 결과를 본 뒤에는 바꾸지 않습니다. 바꿔야 할 사정이 생기면 이 문서에 날짜와 사유를 남기고, 바뀐 기준은 다음 판정부터 적용합니다.

## 0. 출발점

- 지금까지의 연구 데이터는 2026-01-01 ~ 2026-10-06 하나뿐입니다(9개월, 12종목). 이 데이터는 TRAIN / VALID / HOLDOUT으로 이미 모두 소진되었습니다.
- 그 결과 켜진 알파 3개(`htf_trend`, `intraday_levels`, `momentum_burst`)는 HOLDOUT에서 평균 -0.035R로 엣지가 확인되지 않았습니다(`docs/RESEARCH.md` 5~7절).
- 반면 **2022~2025년 4년치는 어떤 알파 설계에도 쓰이지 않았습니다.** 하락장(2022), 횡보·회복(2023), ETF 상승장(2024), 2025년까지 국면이 다양합니다.
- 공개 아카이브의 범위: 1분봉은 BTC 2020-01부터, 대부분 알트 2020-09부터, SUI는 2023-05부터 있습니다. 포지셔닝 지표는 BTC 2020-09, 알트 2021-12부터 있습니다.

남은 작업의 축은 두 가지입니다.

1. 4년치 미사용 데이터로 현재 알파를 **정직하게 다시 판정**하고, 여러 국면을 거친 데이터로 알파를 다시 연구합니다.
2. 봇 자체를 실제 운영 품질로 끌어올립니다. 대상은 포트폴리오 구성, 자기 개선의 통계적 엄밀성, 전체 시스템 리플레이 검증, 운영 UX입니다.

## 1. 데이터 구획 (사전 등록)

| 구획 | 기간 | 용도 | 규칙 |
|---|---|---|---|
| **OOS-1 / 이후 TRAIN** | 2022-01-01 ~ 2024-12-31 | P1에서 현재 알파를 **한 번** 판정. 그 뒤 P2의 TRAIN | P1 판정 전까지는 알파 코드·파라미터를 바꾸지 않음 |
| **SEALED-2025 (소진됨)** | 2025-01-01 ~ 2025-12-31 | P2 최종 시험. **딱 한 번** 개봉. 2026-10-11 `vol_breakout_dbox` 확인 시험에 썼음(탈락, [`docs/SEALED_2025.md`](SEALED_2025.md)) | 그때까지 코드로 봉인, 개봉 3회는 원장에 기록. 시험 뒤 봉인 해제(`seal.SPENT`): 이제 일반 이력이며 이후 연구의 TRAIN에 쓸 수 있음 |
| **RECENT (소진됨)** | 2026-01-01 ~ 2026-10-06 | P2의 VALID | 현 알파 설계에 쓰였으므로 신규 알파 선택용으로만 사용 |
| **FORWARD** | 2026-10-07 ~ | 실시간 페이퍼, 이후 추가 시험 | 쌓이는 대로 다음 봉인 구획 후보 |

- 연구용 장기 DB는 `data/longhist/heartless.db`입니다(`HEARTLESS_DATA_DIR=data/longhist`). 기존 `data/research`와 운영 DB는 건드리지 않습니다.
- 핵심 유니버스는 지금의 12종목입니다(BTC ETH SOL XRP DOGE ADA AVAX LINK LTC BCH BNB SUI). SUI는 2023-05부터 포함됩니다.
- 확장 유니버스는 코인 간 비교 연구용으로 8종목을 추가합니다(DOT ATOM NEAR FIL ETC TRX UNI AAVE). 2022-01 이전에 상장되어 지금까지 거래되는 종목만 골랐습니다. 기간 도중 상장폐지·심볼 변경된 종목(예: MATIC)은 생존 편향 쪽으로 기울지 않도록 **기록만 하고** 제외합니다.

## 2. 작업 패키지

각 패키지는 담당 파일, 산출물, 수용 기준을 가집니다. 모든 구현은 기존 테스트 전부 통과, 새 기능의 테스트 추가, 커밋, 푸시로 끝납니다.

### P0. 장기 데이터와 랩 기간 기능

**목표:** 2022-01 ~ 2026-10-08 장기 데이터를 받고, 랩이 기간·연도·봉인을 다루게 합니다.

**산출물**
- `heartless fetch`에 장기 수집 옵션을 추가합니다(`--start 2022-01-01 --end ... --symbols ...`). 끊겨도 이어받기가 되어야 하고, 이미 저장된 구간은 건너뜁니다.
  - 수집 결과는 종목별 1분봉 / 펀딩 / 지표의 행 수, 구멍(gap), 범위로 `data/longhist/coverage.json`에 남깁니다.
- `heartless/learning/seal.py`:
  - 봉인 구간을 정의합니다(기본: 2025 전체).
  - `check_window(start, end, unseal)`는 겹치면 `SealedError`를 냅니다.
  - 개봉하면 `docs/results/seal_ledger.jsonl`에 시각, 명령, 커밋을 append합니다.
  - lab, discover, optimizer, 장기 평가 경로가 모두 이 검사를 거칩니다.
- `heartless lab`:
  - `--years 2022,2023,2024` 또는 `--start/--end`를 받고, 결과를 연도별로 나눠 보여줍니다.
  - `--by-side`로 롱/숏을 나눠 보여줍니다.
  - 긴 기간은 (종목 × 연도) 작업으로 쪼개 병렬 실행합니다. 각 조각에는 워밍업을 붙이고, 조각 경계에서 강제 청산된 거래에는 `boundary=True`를 표시합니다.
  - 결과 JSON을 `--out docs/results/<이름>.json`으로 저장합니다(요약, 연도별, 알파별, 롱/숏, 일 단위 t).
- `apply_overrides`: `--set` 값이 ParamSpec 격자로 반올림되면 실제 실행값을 경고로 출력합니다(RESEARCH.md 9절).

**수용 기준**
- 12+8종목의 장기 데이터가 저장되어 있습니다. 대상 기간에서 1분봉 누락이 0.5% 미만이고, 누락 구간 목록이 coverage.json에 있습니다.
- 2025 구간을 개봉 없이 평가하려 하면 거부됩니다(테스트).
- 연도 분할 랩 결과가 분할하지 않은 결과와 거래 수 ±2% 안에서 일치합니다(경계 효과 측정 테스트 또는 보고).
- 12종목 × 3년 단일 알파 평가가 4코어에서 30분 안에 끝납니다(시간을 보고에 기록).

### P0b. 엔진 정합성 수정 (RESEARCH.md 9절)

P1 판정 전에 들어가야 합니다. P1은 실제 출하될 엔진으로 평가해야 하기 때문입니다.

- 레짐 전환 청산을 알파 이름에서 신호 속성으로 바꿉니다. `Decision`/`Signal`에 `exit_on_regime_change: bool`을 두고, 해당 알파가 옵트인합니다. 기본 켜짐 알파 3개의 동작은 바뀌지 않아야 합니다.
- 포스트온리 재호가 시 수량을 새 진입가와 손절 기준으로 다시 계산해, 위험액이 예산(`risk_per_trade_pct`)을 넘지 않게 합니다. 줄인 수량이 최소 수량 미만이면 취소합니다.
- 신호별 유효 기간을 둡니다. `Decision.entry_ttl_bars`(기본 None이면 기존 동작)를 넣어, 1시간 알파가 리테스트 지정가를 걸어 둘 수 있게 합니다.
- **수용 기준:** 새 테스트 통과. 켜진 3개 알파의 2026 TRAIN 랩 결과가 수정 전과 같거나, 차이가 재호가 위험 축소로만 설명되어야 합니다(거래 목록 비교 보고).

### P1. 현재 알파의 표본 외 판정 (OOS-1, 한 번만)

**절차**
1. P0, P0b 커밋 이후의 코드로, 알파 코드와 파라미터를 고정한 채 실행합니다.
2. 9개 알파 각각을 단독(`--alpha`, 출하 기본 파라미터)으로 OOS-1(2022-01-13 ~ 2024-12-31, 12종목)에서 평가합니다. 명목 비용과 스트레스 비용을 각각 한 번씩 돌립니다.
3. 판정 후 기본 구성(켜질 알파들)의 **공동 포트폴리오**(1만 USDT 계정 하나, 운영 리스크 설정)를 연도별로 한 번 돌려 수익률, 최대낙폭, PF를 보고합니다. 이 결과는 정보로만 쓰고 판정에 쓰지 않습니다.
4. 결과는 `docs/OOS_2022_2024.md`와 `docs/results/p1_*.json`에 남깁니다. 결과를 본 뒤 파라미터 재조정은 금지합니다.

**사전 등록 판정 기준**

| 대상 | 켜짐 유지 / 켜기 조건 (모두 충족) |
|---|---|
| 현재 켜진 3개 (`htf_trend`, `intraday_levels`, `momentum_burst`) | 합산 평균R > 0, **t_day ≥ 2.0**, 3개 연도 중 **2개 이상** 평균R > 0, 스트레스 합산 평균R > 0 |
| 현재 꺼진 6개 (`trend_pullback`, `squeeze_breakout`, `mean_reversion`, `funding_fade`, `sweep_reversal`, `positioning`) | 합산 평균R ≥ +0.05, **t_day ≥ 3.0**, **3개 연도 모두** 평균R > 0, 스트레스 합산 평균R > 0 |

- 꺼진 알파에 더 엄격한 기준을 쓰는 이유는 두 가지입니다. 이미 2026년 데이터에서 탈락했고, 6개를 동시에 검정하기 때문입니다(`max(3, sqrt(2 ln N))` 규칙).
- `discovered`는 규칙이 없으므로 판정 대상이 아닙니다.
- 기준을 통과하지 못한 켜진 알파는 `enabled_by_default=False`로 바꿉니다. 설계 지문이 바뀌므로 운영 봇의 저장 챔피언도 자동으로 따라갑니다.
- **켜진 알파가 하나도 남지 않으면** 봇은 페이퍼 모드에서 거래 없이 학습(리서치, 발굴, 챌린저)만 하는 상태가 됩니다. 이것도 정상적인 결론으로 받아들입니다. 시작 메시지에 이 상태를 명확히 표시합니다.

### P2. 다국면 연구 2차

P1 이후에 진행합니다.

- **데이터:** TRAIN = OOS-1(2022~2024), VALID = RECENT(2026), SEALED = 2025.
- **시장 컨텍스트 인프라** (`heartless/data/context.py`):
  - 유니버스 전체의 1시간 단위 단면(cross-sectional) 피처를 계산합니다. 상대강도 순위(24h/7d), BTC 추세·레짐, 시장 폭(EMA 위 종목 비율), 분산도, 시장 전체 OI 변화, 펀딩 단면 순위.
  - 오프라인에서는 장기 DB로 `market_context` 테이블을 미리 만들고, 랩 워커가 이를 읽습니다. 운영에서는 같은 함수로 온라인 계산합니다. 두 결과가 같다는 동등성 테스트가 필수입니다.
  - 알파는 `ctx.market`으로 접근합니다.
- **연구 대상**
  - P1에서 탈락한 알파를 TRAIN에서 재설계합니다.
  - 코인 간 비교 알파: 상대강도 지속/반전, 시장 폭 필터, BTC 선행.
  - 다년 데이터로 발굴 엔진을 재실행합니다.
- **선택 기준 (사전 등록)**
  - TRAIN: 시도한 변형 수 N을 기록하고, t_day ≥ `max(3, sqrt(2 ln N))`. 3개 연도 중 2개 이상 평균R > 0. 스트레스 평균R > 0.
  - VALID: 평균R > 0, t_day ≥ 1.0. (2026-10-10 변경, 6절 참조. 원래 기준은 t_day ≥ 1.5)
  - 시도 횟수 N은 `docs/results/p2_trials.jsonl` 시도 원장(P2a에서 구현)으로 셉니다. 계열(family)별 N을 쓰고, 규칙 대량 탐색(발굴 엔진)은 탐색한 규칙 수 전체를 N으로 씁니다.
  - 통과한 알파만 기본으로 켭니다.
- **최종 시험 (SEALED-2025, 한 번)**
  - 최종 기본 구성 전체의 공동 포트폴리오와 알파별 결과를 보고합니다.
  - 개봉 후에는 재조정을 금지합니다.
  - 예외는 하나입니다. SEALED에서 평균R < -0.10이고 t_day < -2.0인 알파는 끕니다(심각한 실패 규칙).
  - SEALED 공동 포트폴리오가 손실이면 README와 시작 메시지에 "실거래 비권장"을 유지합니다.

### P3. 포트폴리오 구성

- **신호 일괄 결정**
  - 같은 봉 마감 시각에 여러 종목에서 나온 진입 후보를 모은 뒤, 기대값 순(밴딧 사후 평균 × 신뢰도, 메타 모델이 켜져 있으면 그 기대R)으로 정렬해 한도 안에서 받습니다.
  - 지금은 먼저 처리된 종목이 한도를 차지합니다(RESEARCH.md 6절, 9절).
  - 운영 경로(app)와 공동 백테스터가 **같은 할당기 코드**를 써야 합니다.
- **상관 기반 한도**
  - 같은 방향 "개수" 한도를 위험 예산 한도로 바꿉니다. 총 개방 위험 ≤ `MAX_TOTAL_RISK_PCT`, 같은 방향 위험 ≤ `MAX_SAME_DIRECTION_RISK_PCT`.
  - BTC 베타(최근 30일 1시간 수익률)로 가중합니다.
  - 기존 개수 한도는 상한으로 남깁니다.
- **채택 기준**
  - 공동 백테스트에서 TRAIN(2022~2024) 기준 수익률/최대낙폭 비율이 FIFO보다 좋고, VALID(2026)에서 나쁘지 않아야 기본값으로 켭니다.
  - 기준에 못 미치면 기능만 넣고 기본은 끈 상태로 둡니다(보고서에 수치를 남김).

### P4. 자기 개선 견고화

- **승격 판정**
  - 챌린저와 챔피언의 비교를 거래 단위에서 **일 단위 군집** 통계로 바꿉니다.
  - 조건은 최소 거래 일수(`PROMOTION_MIN_DAYS`, 기본 14)와 최소 거래 수, 그리고 일 단위 차이의 t ≥ 1.0 + 낙폭 비열등입니다.
  - 퇴출도 같은 통계를 씁니다.
- **알파별 킬 스위치**
  - 운영(페이퍼·실거래) 결과로 알파별 누적R CUSUM을 추적합니다. 기대치(랩 VALID 평균R)에서 유의하게 이탈하면 그 알파를 즉시 끄고 텔레그램으로 알립니다.
  - 끄기는 안전 방향이므로 챌린저 검증 없이 바로 적용합니다. 다시 켜기는 리서치 챌린저 경로로만 합니다.
- **리서치 창 확대**
  - 30일 창은 1시간 알파에 너무 짧습니다. 리서치 lookback 기본값을 120일로, 데이터 보존을 180일로 늘립니다.
  - 아카이브 백필이 이를 채우고, 폴드 확인은 일 단위 t로 합니다.
- **실행 품질 감시**
  - 실현 슬리피지와 수수료를 모델값과 비교해 `/status`와 일일 보고에 표시합니다.
  - 차이가 크면 백테스트 슬리피지 설정을 갱신하라고 제안합니다(자동 변경은 하지 않음).

### P5. 전체 시스템 리플레이 soak 테스트

- `heartless replay --start --end --speed max`:
  - 실제 `HeartlessApp`을 가상 시계와 리플레이 거래소(저장된 1분봉을 순서대로 공급하는 PaperAccount)로 돌립니다.
  - 텔레그램은 메시지를 수집하는 스텁으로, 웹은 끈 상태로 둡니다.

- 매 분 검사하는 불변식은 다음과 같습니다. 위반이 하나라도 있으면 실패입니다.

  - 모든 개방 포지션에 보호 손절이 있습니다.
  - 고아 주문이 없습니다.
  - 실현 손익 + 수수료 + 펀딩의 합이 잔고 변화와 같습니다.
  - 처리되지 않은 예외가 없습니다.
  - 일일 PnL 보고값이 거래 기록과 일치합니다.
  - 메모리 증가가 상한 안에 있습니다.
- pytest에는 3일짜리 짧은 리플레이를 넣고, 60일 리플레이를 1회 돌린 결과를 보고합니다.

## 3. 순서와 병렬화

```
Wave A  [P0 데이터·랩·봉인]  ‖  [P0b 엔진 정합성]                       — 완료
Wave B  [P1 OOS 판정 (한 번)]  ‖  [P5 리플레이 soak 하네스]              — 완료
Wave C  [P4 자기 개선 견고화 + 정지 해소]  ‖  [P2a 연구 인프라]           — 완료
Wave D  [P2 연구 2차: 가설 계열별 탐색(TRAIN) → VALID 관문 → 알파 구현]   — 완료 (VALID 통과 0)
Wave D2 [P3 포트폴리오 구성 (P2 알파 기준)] → [SEALED-2025 최종 시험 (한 번)]
Wave E  [P6 UX·문서] → 전체 검토
```

- 동시 실행 에이전트는 최대 2개입니다(4코어). 같은 Wave의 두 작업은 담당 파일이 겹치지 않게 나눕니다.
- Wave A에서 P0는 `data/archive.py`, `cli.py`(fetch/lab), `learning/lab.py`, `learning/seal.py`를 맡고, P0b는 `execution/engine.py`, `strategy/base.py`, `strategy/risk.py`, 알파 파일을 맡습니다.
- Wave C에서 P3는 `engine.py`, `risk.py`, 할당기, `backtester.py`를 맡고, P4는 `learning/research.py`, `optimizer.py`, `bandit.py`, `store.py`(새 테이블)를 맡습니다. `app.py` 배선은 Wave 통합 단계에서 한 번에 합칩니다.
- 각 Wave가 끝나면 메인 루프가 전체 테스트를 돌리고, 결과를 검토하고, 커밋·푸시합니다. 연구 판정(P1, P2 최종)은 결과를 그대로 기록하고 기준대로 적용합니다.
- 구현은 Opus 5.5(effort xhigh) 에이전트가 맡고, 계획·검증·통합은 메인 루프가 맡습니다.

## 6. 변경 기록

### 2026-10-10: P1 결과에 따른 순서 변경과 P2 기준 조정 (P2 시작 전)

- **P1 결과:** 9개 알파 모두 2022~2024에서 탈락했고, 출하 기본 활성 알파는 0개입니다(`docs/OOS_2022_2024.md`). 그 결과 두 가지가 바뀝니다.
  1. **P4를 앞당깁니다.** 챔피언이 거래하지 않으면 챌린저와 비교할 거래가 없어 승격이 멈춥니다(`research.py` `evaluate_challengers`). 봇이 스스로 알파를 다시 켤 길이 막혀 있으므로 이것이 최우선 결함입니다. 그래서 P4에 다음을 추가합니다.
     - 챔피언 거래가 부족할 때 쓰는 **절대 기준 승격 경로**.
     - 알파별 표본 외 증거 기록(evidence registry). OOS에서 탈락한 알파를 다시 켜려면 더 강한 페이퍼 증거가 필요합니다.
  2. **P3는 P2 뒤로 미룹니다.** 엣지 없는 신호들 사이의 순위 매기기는 측정할 대상이 없기 때문입니다. P2a(연구 인프라)를 Wave C에서 P4와 병렬로 진행합니다.
     - P2a의 범위: 지표 계산 가속(결과 비트 단위 동일), 시장 컨텍스트, 다년·단면 발굴, 시도 원장.
     - P2a에서는 어떤 가설의 성과도 측정하지 않습니다(시도 원장을 깨끗하게 유지하기 위해서입니다).
- **P2 VALID 기준을 t_day ≥ 1.5에서 1.0으로 낮춥니다.** P2 후보의 성과는 아직 아무것도 보지 않았습니다.
  - 근거는 검정력입니다. VALID는 9개월입니다. 연환산 일 단위 샤프 1.5인 진짜 엣지의 기대 t는 약 1.3이므로, t ≥ 1.5에서는 절반 이상이 탈락합니다.
  - 과적합 방지는 TRAIN 관문이 맡습니다. 3년 t_day ≥ 3이면 연환산 샤프가 약 1.7 이상이어야 합니다. 이 기준은 그대로 둡니다.
  - SEALED 최종 시험 규칙도 그대로입니다.

|---|---|---|
| `ts_trend` | 일 단위 시계열 추세(다일 수익률 부호, 돌파, 변동성 정규화), ATR 추적 손절 | 하루 1회 결정, 수일~수주 |
| `xs_rank` | 코인 간 상대강도 순위의 지속(모멘텀) 또는 반전, `ctx.market` 순위 사용 | 고정 시각 1회, 24~72시간 |
| `funding_carry` | 펀딩비 단면 순위(높으면 숏, 낮으면 롱). 펀딩 수입 포함 | 8~72시간 |
| `positioning_flow` | OI 변화·가격·탑트레이더 비율 극단의 4시간~1일 반응 | 4시간~1일 |
| `vol_breakout` | 변동성 수축 뒤 확장 돌파, BTC 레짐 필터 | 4시간~수일 |
| `discovery_daily` | 발굴 엔진 다년 실행(시간·일 단위 격자, 컨텍스트 피처, 요일·시간대 피처). 발굴 엔진 내부 검증 구간도 TRAIN 안에서 잡습니다(예: 2024년) | 템플릿별 |

**절차**
1. 계열 연구자는 TRAIN만 봅니다. 평가한 모든 구성은 `--tag <계열>`로 시도 원장에 기록합니다. 기록 없이 돌린 평가는 연구 위반입니다.
2. 계열당 lab 구성은 약 25개 이내로 제한해, 가설을 먼저 정하고 적은 변형만 시험합니다. 계열별 최종 후보는 최대 2개입니다. TRAIN 관문(모두 충족):
   - t_day ≥ `max(3, sqrt(2 ln N_계열))`
   - 평균R ≥ 0.05
   - 3개 연도 중 2개 이상 평균R > 0
   - 스트레스 평균R > 0
   - `discovery_daily`의 N은 탐색한 규칙 수 전체입니다.
3. 관문 담당(별도 에이전트)은 TRAIN 관문을 통과한 후보만 VALID에서 **한 번씩** 평가합니다. VALID 관문은 평균R > 0, t_day ≥ 1.0입니다. 통과한 알파만 기본으로 켜고, 증거 기록(evidence.json)의 verdict를 `passed`로 바꿉니다.
4. 이어서 P3(포트폴리오 구성)를 통과 알파 기준으로 진행합니다. 통과 알파가 없으면 P3는 기능만 넣고 기본은 끕니다.
5. SEALED-2025 최종 시험을 한 번 합니다(P2 절의 규칙 그대로).
6. 결과는 통과 여부와 관계없이 `docs/RESEARCH_P2.md`에 계열별로 모두 기록합니다. 시도 수, 최고 후보, 탈락 사유를 남깁니다.

### 2026-10-11: 챌린저 승격을 판정점 방식으로 교체, 리서치 주기 6시간 (Wave D C2-B, 실제 챌린저 성과 미관측)

| 판정점 | 절대 t_day | 상대 일별 차이 t | 탈락 알파 절대 | 탈락 알파 상대 |

  - 절대 경로 낙폭 한도는 10R × √(n/30)입니다.

  - 승격할 때는 챌린저의 변경분만 그 시점 챔피언에 적용합니다.

**이유**
- 매시간 재판정은 같은 데이터를 수백 번 보는 다중 비교였습니다. 보정 모델에서 엣지 0 챌린저의 오승격률이 절대 경로 최대 28%, 상대 경로 최대 48%였습니다.
- 새 기준은 120개 시나리오 몬테카를로로 정했습니다: 하루 1~5건, 두꺼운 꼬리 R, 승률 30~60%, 같은 날 상관 0 / 0.3, 상대 경로 구조 3가지. 독립 재실행(시나리오당 20,000개) 결과 오승격률은 최악 4.71%(목표 5% 이하), 탈락 알파는 1.96%(목표 2% 이하)였습니다(`tools/calibrate_promotion.py`, `docs/results/c2b_promotion_calibration.json`).
- 기준은 시뮬레이션만으로 정했습니다. 실제 챌린저의 페이퍼 성과는 보지 않았습니다.

**알려진 한계 (C2-B 리뷰)**
- 거래 사이의 의존이 UTC 날짜를 넘으면 오승격률이 목표보다 높습니다.
  - 정시 기준으로 12시간 어긋난 일별 공통 요인: 6.3%
  - 날짜 간 AR(1) 공통 요인 φ = 0.3 / 0.6: 8.3% / 14.1% (탈락 알파 3.5% / 8.0%)
  - 10~30일 단위로 바뀌는 평균 0 엣지: 6.3% ~ 17.3%
- 검정력이 낮습니다. 90일 안에 진짜 +0.10R 엣지를 찾을 확률은 약 15%, +0.20R은 약 35%입니다.
- 챌린저를 여럿 시험할수록 누적 오승격 확률이 커집니다. 90일 재시도 금지는 똑같은 변경만 막습니다.
- 다음 단계에서 판단할 일: 날짜 간 의존 시나리오로 재보정할지, 날짜를 넘는 분산 추정(예: 블록 분산)으로 바꿀지. 바꾸면 이 절에 다시 기록합니다.

**리서치 주기 240 → 360분**
- P2a 가속 뒤 120일 리서치 한 사이클을 연구 DB 사본에서 다시 쟀습니다: 7,833초(코어 1개), 최대 1,628MB. 4시간 주기의 54%입니다. 6시간이면 약 36%입니다.

### 2026-10-11: SEALED-2025 사용 방식 변경 — 단일 후보 확인 시험 (개봉 전 사전 등록)

### 7.1 북극성

이 프로젝트의 목표는 실제로 돈을 버는 것입니다. 그래서 검증되지 않은 엣지로는 실거래하지 않습니다. 그것이 돈을 잃는 가장 확실한 길이기 때문입니다. 시스템의 가치는 "지금 돈을 번다"가 아니라 "엣지를 찾고, 검증하고, 사라지면 끄는 일을 사람 없이 계속한다"에 있습니다. "돈을 번다"는 목표는 관문을 낮춰서가 아니라, 서로 다른 수익원(기회 계열)을 늘려서 이룹니다.

### 7.2 지금 루프가 못 하는 것

1. **가설 생성이 유한합니다.** 리서치 사이클은 기존 알파의 파라미터만 조정하고, 발굴 엔진은 고정된 피처 집합에서만 규칙을 찾습니다. 새 알파는 모두 사람(에이전트)이 썼습니다.
2. **비용 구조가 고정입니다.** 모든 평가가 테이커 5bp 기준입니다. 메이커 2bp 체결을 전략 수준에서 쓰지 않습니다.
3. **방향 예측 밖의 수익원이 없습니다.** 펀딩 캐리 같은 구조적 수익원을 다루지 않습니다.
4. **전진 검증이 비공식적입니다.** 2025와 2026 VALID가 소진된 뒤 새 후보를 확인할 봉인 구획이 없습니다.
5. **배포되어 있지 않습니다.** 실시간 페이퍼 데이터가 쌓이지 않아 챌린저, 킬 스위치, 발굴이 멈춰 있습니다.

  - 나머지 `xs_rank_mom`, `funding_carry_xs`, `discovered`도 2026 구간 리플레이의 리서치 사이클·발굴이 평가할 수 있었으므로 보수적으로 같게 봅니다.
- 엔진, 백테스터 같은 공용 기반 코드는 세지 않습니다.
- LLM이 제안한 알파도 2026을 본 코드로 취급합니다. 모델의 학습 데이터에 2026 시장이 들어 있을 수 있기 때문입니다(7.10절).
- **남는 오염**: 연구자는 P2 VALID 결과(2026의 추세·포지셔닝·돌파 알파 성적)를 이미 압니다. 줄일 수 없는 오염이므로 결과 문서에 적어 둡니다.

### 7.4 공통 규칙

**연구 유니버스** (모든 계열, `docs/UNIVERSE.md` 3절)
- 달 m의 구성원은 직전 달 일별 거래대금 중앙값 상위 40개 USDT 무기한입니다(`--universe top40`).
  - 스테이블코인은 제외합니다.
  - m의 시작에 상장 30일 이상이어야 합니다. 재상장은 새 첫 거래부터 셉니다.
  - 상장폐지된 종목도 그대로 포함합니다.
- 진입은 그 종목이 구성원인 달에만 셉니다(`universe.member_trades`). 보유 중에 구성원 자격이 끝나도 청산 규칙대로 유지합니다.
- **상장폐지**: 종목의 마지막 거래 시간에 그 시간 종가로 강제 청산합니다. 슬리피지는 명목의 5배(스트레스 10배)입니다. 공지 날짜는 데이터에 없으므로 진입을 미리 막지 않습니다. 미리 막으면 미래 정보를 쓰게 됩니다.
- 고정 종목 목록(핵심 12, 확장 20)을 유니버스로 삼아 관문을 판정하지 않습니다. 그 20종목의 데이터는 구성원인 달에 다른 종목과 똑같이 쓰고, 고정 목록 자체는 평가기 동등성 확인에만 씁니다.

**비용**

| 시장 | 수수료 (테이커 / 메이커) | 슬리피지 (시장가) | 스트레스 |
|---|---|---|---|
| 선물 (USDⓈ-M) | 5bp / 2bp | 1.5bp | 수수료 ×1.5, 슬리피지 ×2 |
| 현물 | 10bp / 10bp | 3bp | 수수료 ×1.5, 슬리피지 ×2 |

- 펀딩은 정산 시각 s에 열려 있던 포지션에만 붙습니다(s 전에 진입하고 s 뒤에 청산). 정산 시각은 종목·시기마다 저장된 정산 기록을 따릅니다. 1·2·4시간 주기도 있습니다.
- **시각 규약**: "시각 t 마감"은 1시간 봉 [t − 1h, t)의 마지막 순간(t − 1ms)입니다. 그래서 시각 s 마감에 청산한 포지션은 s의 정산을 받지도 내지도 않고, s 정산값은 시각 s + 1h 마감부터 결정에 씁니다.
- 결정은 봉 마감 시각까지의 정보만 씁니다. 체결가는 그 마감가로 만든 합성 호가의 반대쪽에 슬리피지를 더한 값입니다(lab의 `PaperAccount`와 같음).

**통계**
- **방향 계열** (R 단위)
  - 평균R, PF, t_day를 씁니다. t_day는 거래를 UTC 청산일로 묶은 군집 t입니다(`lab.group_stats`와 같은 추정량).
  - 연도는 진입 시각 기준입니다.
- **캐리·중립 계열** (자본 C 대비 %)
  - 일별 순손익은 두 다리를 UTC 일 끝에 시가평가해 구합니다. 거래 없는 날은 0으로 넣습니다.
  - t = 일별 순손익 평균 / (표준편차 / √일수)
  - 연환산 순수익률 = 일평균 × 365
  - 최대낙폭은 일별 자산 곡선 기준입니다. 연도와 분기는 달력 기준입니다.
  - 일별 캐리 손익은 자기상관이 있으므로, 주 단위 블록 t도 정보용으로 함께 남깁니다.

**평가기**

| 평가기 | 쓰는 계열 | 데이터 |
|---|---|---|
| lab (1분봉 엔진, `PaperAccount` 체결) | `maker_exec`, `discovery_f`, 1분 결정 알파 | 상위 40 구성원 1분봉 (F-data-1m) |
| 시간 단위 방향 평가기 `learning/hourly.py` (F-pre-A) | `liq_cascade`, `event_funding`, 1시간 이상 결정의 AI 제안 | `universe.db` 1시간봉·펀딩, OI·프리미엄 1h (F-data-h) |
| 두 다리 중립 평가기 (F-pre-A의 공용 틀, 계열 규칙은 계열 연구자) | `carry_neutral`, `pairs_neutral` | `universe.db` 선물·현물 1시간봉, 펀딩 |

- 시간 단위 평가기는 손절, 목표, 시간 청산만 다룹니다. 본전 이동과 추적 손절은 없습니다.
- 같은 1시간 봉에서 손절과 목표가 함께 닿으면 손절이 먼저입니다.
- 1시간 계열 후보는 확인 시험 전에 운영 엔진용 알파 모듈로 옮깁니다. 그 모듈은 장기 DB 20종목의 TRAIN 기간에서 평가기와 결정(시각, 방향)이 99% 이상 같아야 합니다.

**시도 원장과 연구 절차**
- 원장은 그대로 `docs/results/p2_trials.jsonl` 하나입니다(덧붙이기만). 계열 태그는 7.5절 표의 것을 씁니다.
- 모든 평가기는 평가한 구성마다 스스로 원장에 한 줄을 남깁니다. lab과 discover는 `--tag`로, 시간 단위·중립 평가기는 `screen` 줄로 남깁니다.
- N은 계열 원장의 서로 다른 구성 수입니다. 발굴은 탐색한 규칙 수를 셉니다. `maker_exec` 후보의 N에는 원래 계열의 N을 더합니다(7.7.2).
- 구성 해시에 체결 방식(`exec`)이 들어가야 합니다(F-pre-A). 같은 구성의 스트레스, VALID, FORWARD 재실행은 N을 늘리지 않습니다.
- 계열 연구자는 TRAIN만 봅니다.
  - 자기 후보를 얼리기 전에는 VALID·FORWARD 결과 파일과 결과 문서의 확인 절을 읽지 않습니다.
  - 원장에 없는 평가는 연구 위반입니다.
- 관문 담당은 별도 에이전트입니다. 하는 일은 세 가지입니다.
  - 결과 파일로 TRAIN 관문을 다시 계산합니다.
  - 미래 참조를 감사합니다. 결정 봉에서 자른 뷰와 전체 뷰의 결정을 비교하는 방식이고, `tests/test_p2_gate.py`와 같습니다.
  - 확인 시험을 후보당 한 번 돌립니다.

### 7.6 관문

**TRAIN 관문: 방향 계열** (`maker_exec`, `liq_cascade`, `event_funding`, `discovery_f`, `ai_hypothesis`). 모두 충족해야 합니다.
- t_day ≥ max(3, √(2 ln N))
- 평균R ≥ 0.05
- 2022·2023·2024·2025 중 3개 이상 연도에서 평균R > 0
- 스트레스 평균R > 0

**TRAIN 관문: `regime_switch`** (TRAIN-B에서 판정)
- 방향 계열의 네 조건을 봅니다. 연도 조건은 2024와 2025 모두 평균R > 0입니다.
- 추가 조건: 거른 결과의 평균R이 거르지 않은 구성 요소 합집합의 TRAIN-B 평균R보다 커야 합니다.

**TRAIN 관문: 캐리·중립 계열** (`carry_neutral`, `pairs_neutral`). 모두 충족해야 합니다.
- t(일별 순손익) ≥ max(3, √(2 ln N))
- 연환산 순수익률 > 2%. 수수료와 슬리피지를 모두 뺀 뒤의 값입니다. 초안의 "비용 + 2%", 곧 총수익이 비용보다 연 2%p 이상 커야 한다는 뜻입니다.
- 최대낙폭 < 3%
- 모든 연도의 순손익 > 0. `carry_neutral`은 2022~2025, `pairs_neutral`은 TRAIN-B의 2024·2025입니다.
- 스트레스 비용의 연환산 순수익률 > 0
- 강제 청산 0건
- `pairs_neutral`은 TRAIN-A에서 구성을 고르고, 관문은 TRAIN-B 결과로 판정합니다. N은 A·B 전체입니다.

**확인 관문** (후보당 한 번)

| 구획 | 방향 계열 | 캐리·중립 계열 |
|---|---|---|
| VALID-F (2026-01-13 ~ 09-30) | 평균R > 0, t_day ≥ 1.0 | t ≥ 1.0, 세 분기(01-13 ~ 03-31, 04-01 ~ 06-30, 07-01 ~ 09-30) 모두 순손익 > 0 |
| FORWARD (등록한 블록 묶음) | 평균R > 0, t_day ≥ 1.0 | t ≥ 1.0, 묶음(3블록, 한 분기) 순손익 > 0 |

- 스트레스 결과는 정보로 남기고 판정에는 쓰지 않습니다(P2 VALID와 같음).
- **검정력**: 엣지가 0인 후보가 확인 관문을 넘을 확률은 약 16%입니다(t ≥ 1.0 단측). 과적합 방지는 TRAIN 관문이 맡습니다.

**통과하면**
- **방향 계열**
  - 그 알파를 `enabled_by_default=True`로 바꿉니다. `maker_exec`이면 체결 방식도 출하 기본값으로 바꿉니다.
  - 증거 기록 verdict를 `passed`로 바꿉니다. TRAIN·확인 수치, 체결 방식, 근거 문서를 함께 남깁니다.
  - 킬 스위치 기대R은 min(TRAIN, 확인) 평균R입니다.
- **캐리·중립 계열**
  - 그 전략 엔진을 페이퍼에서 기본으로 켭니다.
  - 증거 기록에 전략 항목(`kind: neutral`)을 `passed`로 올립니다.
  - 킬 스위치는 둘 중 하나가 걸리면 작동합니다.
    - 일별 순손익을 TRAIN 일별 표준편차 단위로 잰 CUSUM(k 0.25, h 8, 기대값 = min(TRAIN, 확인) 일평균)
    - 최근 30일 순손익 < 전략 자본의 −1%
- **`regime_switch`**: 국면별 켜짐 표를 출하 기본으로 켭니다.
- **`ai_hypothesis`**: 출하 기본으로 켜지 않습니다(7.10절).
- **실거래**: 어떤 계열이든 졸업 기준(`docs/SELF_IMPROVEMENT.md` 8절)과 소유자의 `/golive` 확인 뒤에만 합니다.

**탈락하면**
- 꺼진(출하하지 않은) 채로 둡니다.
- 확인 시험까지 간 후보는 증거 기록에 `failed`로 올립니다. TRAIN에서 멈춘 구성은 원장과 결과 문서에만 남깁니다.
- 같은 구성 해시는 다시 확인 시험을 받지 않습니다. 고친 변형은 새 구성이므로, 늘어난 N으로 TRAIN 관문부터 다시 거칩니다. 확인 시험은 계열의 확인 후보 상한 안에서만 받습니다.

### 7.7 계열별 프로토콜

#### 7.7.1 `carry_neutral` (F2)

- **가설**: 펀딩이 꾸준히 양수인 무기한에서는 숏 쪽이 펀딩을 받습니다. 같은 수량의 현물 롱으로 가격 노출을 없애면, 펀딩에서 비용을 뺀 만큼이 남습니다. 가격 예측은 하지 않습니다.
  - 반대 방향(선물 롱 + 현물 숏)은 현물 차입이 필요하므로 하지 않습니다.
- **유니버스**: 달 m의 상위 40 구성원 중 다음을 모두 충족하는 종목입니다.
  - 현물 USDT 시장이 있고 짝 검사를 통과함(`docs/results/f0_spot_coverage.json`)
  - 직전 달 현물 일별 거래대금 중앙값 ≥ 500만 USDT
- **결정 시각**: 종목의 정산 시각 s마다, 정산 뒤 첫 마감(시각 s + 1h 마감)에 결정합니다. 이때 s의 정산값까지 압니다.
  - 쓸 수 있는 입력: s까지의 정산 펀딩, 결정 시각의 베이시스, 두 시장의 1h 이력
  - 예상 펀딩(premiumIndex의 실시간 추정치)은 과거 데이터에 없으므로 쓰지 않습니다.
- **규칙**
  - 진입: 최근 k번 정산 평균을 연환산한 값(정산 주기로 환산) ≥ A_in이고, 베이시스 ≥ −0.5%. 선물이 현물보다 0.5% 넘게 싸면 들어가지 않습니다(베이시스가 0으로 돌아오면 이 포지션이 잃음).
  - 청산: 같은 값 ≤ A_out
  - 빈자리보다 후보가 많으면 연환산 값이 큰 순으로 들어갑니다. 동시 보유는 최대 8종목입니다.
- **격자 12개**: k ∈ {3, 9} × A_in ∈ {10%, 20%, 30%} × A_out ∈ {0%, A_in/2}
- **크기와 증거금**
  - 자본 C = 현물 지갑 + 선물 지갑. 종목당 두 다리의 명목은 각각 0.075 C(= 0.6 C / 8)입니다.
  - 선물은 격리 2배(증거금 = 명목/2)이고, 유지 증거금률은 1.5%로 고정합니다.
  - 리밸런스: 선물 종가가 진입가의 130% 이상이면, 현물 일부를 팔고 선물을 같은 비율로 줄여 증거금을 명목/2로 회복합니다(비용 포함).
  - 리밸런스 전에 1h 고가가 청산가에 닿으면 강제 청산으로 셉니다(증거금 전액 손실).
- **비용**: 7.4절. 명목 왕복 약 39bp입니다.
- **관문**: 7.6절 중립 관문(4개 연도). 확인은 VALID-F입니다.
- **통과한 뒤**
  - 운영 캐리 엔진(현물 주문, 지갑 간 이체, 두 다리 대사)을 구현하고 페이퍼로 켭니다.
  - 실거래 조건: 키에 현물 거래와 범용 이체 권한이 있어야 합니다(시작 시 자동 감지. 없으면 시작 메시지에 안내 한 줄). 여기에 졸업 기준과 `/golive`가 더해집니다. 레버리지는 2배 이하입니다.

#### 7.7.2 `maker_exec` (F1, 메이커 체결 프로토콜)

- **대상**: 등록된 알파 15개(`discovered` 제외)를 출하 기본 파라미터로 평가합니다. `vol_breakout_dbox`는 판정받은 구성(`comp_q=1.0`)을 씁니다. 이 계열에서는 파라미터를 다시 조정하지 않습니다.
- **체결 방식은 알파 파라미터가 아닙니다.** 엔진 설정 `params["exec"][알파]`로 둡니다(`taker` 기본 | `maker_m1` | `maker_m2`).
  - 알파의 ParamSpec에 넣으면 파라미터 스키마 지문이 바뀌어, 기존 증거 기록이 모두 `untested`가 됩니다.
  - 구성 해시에는 들어갑니다.
- **체결 방식**
  - `maker_m1`: 시장가 신호를 결정 봉 종가의 포스트온리 지정가로 바꿉니다. 결정 단위 1봉(최대 60분) 안에 안 채워지면 취소합니다. 재호가나 시장가 전환은 없습니다.
  - `maker_m2`(리테스트): 지정가 = 종가 ∓ 0.25 × 신호 ATR입니다(롱은 아래, 숏은 위). 결정 단위 3봉(최대 240분) 뒤 취소합니다. 지정가가 손절을 넘으면 신호를 버립니다.
  - 이미 지정가 신호를 내는 알파는 그 지정가를 그대로 쓰고, 유효 기간만 위 규칙을 따릅니다(재호가 없음).
  - 수량은 지정가와 손절로 다시 계산합니다(거래당 위험 0.5%, P0b 규칙).
- **보수적 체결 모델** (백테스트, 리플레이, 페이퍼 공통, `PaperAccount`)
  - 지정가는 가격이 그 값을 **관통할 때만** 체결됩니다. 매수는 그 1분봉의 저가가 지정가보다 합성 스프레드의 절반 이상 아래로 내려가야 합니다(매도는 반대). 닿기만 해서는 체결되지 않습니다.
  - 주문을 넣은 봉에서는 체결되지 않고, 다음 1분봉부터 셉니다.
  - 그 1분봉의 거래대금이 주문 명목의 20배보다 작으면 그 봉에서는 체결되지 않습니다.
  - 체결가는 지정가, 수수료는 메이커 2bp, 슬리피지는 0입니다. 청산(손절 등)은 지금처럼 테이커입니다.
  - 스트레스 실행은 관통 폭을 합성 스프레드 전체로 늘리고, 수수료 ×1.5, 테이커 슬리피지 ×2를 씁니다.
- **격자 30개** = 알파 15개 × {`maker_m1`, `maker_m2`}. 상한도 30입니다.
- **N**: 후보의 기준 N = N(`maker_exec`) + 원래 계열의 N입니다.
  - P2 원장: `ts_trend` 27, `positioning_flow` 21, `vol_breakout` 23, `discovery_daily` 105,068, `xs_rank` 20, `funding_carry` 7
  - P1의 9개 알파는 원래 계열 N이 0입니다.
- **관문**: 방향 TRAIN 관문(TRAIN-F, top40, lab). 15개 모두 2026을 본 코드이므로 확인은 FORWARD입니다.
- **데이터 조건**: F-data-1m(7.12절)이 필요합니다.
  - 디스크가 모자라면 연도 순환 방식으로 돌립니다. 한 해의 1분봉만 받아 30개 구성 × 명목·스트레스를 모두 돌리고, 거래 목록을 저장한 뒤 지웁니다.
  - 격자가 미리 정해져 있어서 이 방식이 가능합니다.
- **통과한 뒤 운영**: 그 알파를 메이커 방식으로 켭니다. 그 알파가 켜져 있는 동안에는 `ORDERBOOK_STREAM`을 켜고 최우선 호가에 포스트온리로 겁니다.

#### 7.7.3 `pairs_neutral`

- **가설**: 같은 요인에 묶인 두 코인의 가격 비가 일시적으로 벌어지면 되돌아옵니다. 시장 방향 노출은 두 다리로 상쇄합니다.
- **짝 형성** (달 m의 시작마다, m 이전 데이터만 씀)
  - 대상: 두 다리 모두 m의 구성원이고, 직전 90일 1h 종가가 있는 짝
  - 계산: 1h 로그수익률 상관 ρ, 로그가격 OLS 기울기 β(0.5 ~ 2로 자름), 스프레드 = log p1 − β log p2, AR(1) 반감기
  - 선택: ρ ≥ ρ_min이고 반감기가 6 ~ 168시간인 짝 중 ρ 상위 K개. 한 종목은 최대 2개 짝에만 들어갑니다.
- **거래** (달 m 동안, β 고정)
  - z = (스프레드 − 직전 720시간 평균) / 직전 720시간 표준편차
  - 진입: |z| ≥ z_in. 스프레드가 높으면 p1 숏, p2 롱입니다.
  - 청산: |z| ≤ 0.5. 손절: |z| ≥ z_in + 1.5. 최대 보유 H가 지나면 청산합니다.
  - 동시 보유는 최대 5짝입니다.
- **크기**: 짝당 첫 다리 명목 0.1 C, 둘째 다리 0.1 C × β, 다리별 격리 2배. 비용은 7.4절(선물 두 다리)이고, 펀딩은 두 다리 모두 붙습니다.
- **격자 16개**: ρ_min ∈ {0.7, 0.8} × z_in ∈ {2.0, 2.5} × K ∈ {5, 10} × H ∈ {72, 168}시간
- **절차**
  1. 격자 전체를 TRAIN-A에서 평가합니다. 첫 형성은 90일 이력이 생기는 2022-03-01입니다.
  2. TRAIN-A t가 가장 높은 구성 최대 2개만 TRAIN-B에서 평가해, 중립 관문(2024·2025)으로 판정합니다.
  3. 확인은 VALID-F입니다.

#### 7.7.4 `liq_cascade`

- **가설**: 강제 청산이 몰린 시간에는 가격이 과하게 움직이고, 이후 몇 시간 동안 일부 되돌아옵니다.
- **과거 대용 사건** (1시간 마감 T, 롱 쪽 기준. 숏 쪽은 대칭)
  - r_1h ≤ −k × σ. σ는 직전 720시간 1h 로그수익률의 표준편차입니다.
  - 거래대금 ≥ v × 직전 720시간 1h 거래대금 중앙값
  - 테이커 매수 비중 ≤ 0.40 (숏 쪽 사건은 ≥ 0.60)
  - 대용 B만: 그 시간의 OI 변화 ≤ −x% (F-data-h의 OI 1h)
- **거래**
  - T 마감가에 진입합니다.
  - 손절 = 사건 봉 저가 − 0.5 × 1h ATR(14)(숏은 대칭). 목표는 없습니다.
  - h시간 뒤 무조건 청산합니다(`time_exit`).
  - 손절폭이 10%를 넘으면 건너뜁니다. 종목당 포지션은 하나입니다.
- **격자**
  - 대용 A 16개: k ∈ {3, 4} × v ∈ {3, 5} × h ∈ {6, 24} × 방향 ∈ {롱만, 양쪽}
  - 대용 B 최대 8개: 대용 A에서 TRAIN t_day 상위 4개에 x ∈ {2%, 4%}
  - 상한은 24입니다.
- **충격 면제**: 이 계열 알파는 `shock_exempt = True`입니다. 7.8절의 진입 중단을 받지 않고, 평가도 면제 상태로 합니다.
- **실시간 청산 스트림**: `forceOrder` 데이터(F5)는 수집만 합니다.
  - 6블록(약 6개월) 이상 쌓이면 그 데이터로 새 TRAIN을 사전 등록합니다.
  - Wave F의 이 계열 후보는 대용치만 씁니다.
- **관문**: 방향 TRAIN 관문. 확인은 VALID-F입니다.

#### 7.7.5 `event_funding`

- **가설**: 정산 직전에는 펀딩을 낼 쪽이 포지션을 줄였다가 정산 뒤 다시 잡습니다. 그래서 정산 전에는 지불 쪽의 반대 방향으로, 정산 뒤에는 되돌아오는 방향으로 압력이 생깁니다.
  - P1에서 탈락한 `funding_fade`의 모듈과 파라미터는 쓰지 않습니다(새 코드).
- **정산 시각** s는 저장된 정산 기록에서 얻습니다. 펀딩 크기는 8시간 기준으로 환산합니다(f × 8 / 정산 주기 시간).
- **E1 (정산 전)**
  - 시각 s − j 마감(j ∈ {1, 2})에 예상 펀딩 f̂의 크기가 f_min 이상이면, 지불 쪽의 반대로 진입합니다(f̂ > 0이면 숏).
  - 시각 s 마감(정산 직전)에 청산합니다. 펀딩은 주고받지 않습니다(7.4절 시각 규약).
  - f̂ = P + clamp(0.01% − P, −0.05%, +0.05%). P는 현재 정산 구간의 1h 프리미엄 지수 평균입니다(거래소 공식. 프리미엄 지수 1h는 F-data-h).
- **E2 (정산 뒤 되돌림)**
  - 시각 s + 1h 마감에 정산값 |f_s| ≥ f_min이면 지불 쪽 방향으로 진입합니다(f_s > 0이면 롱).
  - 시각 s + 1h + h 마감에 청산합니다(h ∈ {3, 6}). 다음 정산 시각 마감을 넘기지 않습니다.
- 손절은 1.5 × 1h ATR(14)이고 목표는 없습니다.
- **격자 12개**: E1 (j 2가지) × f_min ∈ {0.03%, 0.05%, 0.10%} + E2 (h 2가지) × 같은 f_min
  - 프리미엄 데이터가 준비되기 전에는 E2부터 돌립니다.
  - 1분 단위 변형은 F-data-1m 뒤에만 시험하고, 같은 계열 N에 들어갑니다.
- **관문**: 방향 TRAIN 관문. 확인은 VALID-F입니다.

#### 7.7.6 `regime_switch`

- **시작 조건**: Wave F에서 TRAIN 관문을 통과한 방향 후보가 2개 이상일 때만 합니다. 그보다 적으면 "구성 요소 없음"으로 기록하고 건너뜁니다.
- **국면** (매 정시, 1h 데이터와 컨텍스트로 계산하는 고정 정의)
  - 변동성: BTC 30일 실현변동성이 직전 365일 분포의 하위·중간·상위 3분위 중 어디에 있는지
  - 추세: BTC 일봉 종가가 50일 EMA 위인지 아래인지
  - 충격: 7.8절의 충격 상태
- **켜짐 표**: 구성 요소마다, 국면 r에서 TRAIN-A 거래(진입 시각의 국면 기준)가 n_min건 이상이고 평균R ≤ 0이면 r에서 끕니다. 나머지 국면에서는 켭니다.
- **평가**: 구성 요소의 TRAIN-B 거래 목록을 진입 시각의 국면과 켜짐 표로 거릅니다. 종목별 독립 계정으로, lab과 같은 가정입니다.
- **격자 12개**: 국면 해상도 ∈ {변동성 3 + 충격, 추세 2 + 충격, 변동성 × 추세 6 + 충격} × n_min ∈ {30, 60} × 최소 지속 ∈ {없음, 24시간}
- **관문**: 7.6절. 구성 요소가 확인 시험을 이미 썼으므로 확인은 FORWARD입니다. 같은 블록에서 돌린 구성 요소 확인 실행의 거래 목록을 거릅니다.
- **통과하면** 국면별 켜짐 표를 앙상블의 국면별 밴딧 가중치(0/1)로 출하합니다.

### 7.8 급변 대응 프로토콜

시장이 급변하면 새 위험을 늦추고, 알파를 끄는 쪽은 빠르게 합니다. 켜는 쪽 관문은 바꾸지 않습니다.

- 감지와 대응은 `heartless/strategy/shock.py` 하나의 코드로 백테스트, lab, 리플레이, 운영이 똑같이 씁니다(F-pre-B).
- 오프라인 계산과 온라인 계산이 같다는 동등성 테스트가 필수입니다.
- 정의값은 고정이고, 성과를 보고 고치지 않습니다.

**감지** (S0는 1분마다, S1~S3는 정시마다)

| 규칙 | 조건 |
|---|---|
| S0 (기존) | BTC 5분 변동 ≥ 3%이면 15분간 신규 진입 중단. 지금은 운영에만 있으므로 백테스트에도 넣습니다 |
| S1 가격 충격 | BTC 1h 로그수익률 절댓값 ≥ 4 × 직전 720시간 표준편차 |
| S2 변동성 점프 | BTC 24h 실현변동성(√Σ r²_1h) ≥ 2.5 × 직전 30일 같은 값의 중앙값 |
| S3 상관 급등 | 직전 24시간 거래대금 상위 40개 무기한(컨텍스트 `top_n` 구성원 정의와 같음)의 1h 수익률과 BTC 1h 수익률의 24시간 상관 평균 ≥ 0.80이고, 직전 30일 평균 + 0.25 이상 |

- **충격 상태**는 S1~S3 중 하나가 걸린 정시에 시작합니다. 24시간 동안 아무것도 걸리지 않으면 끝납니다.

**대응**
1. **신규 진입 중단**: S1~S3이 걸리면 그 정시부터 2시간 동안 새 진입을 받지 않고(모든 결정 주기), 걸려 있던 진입 지정가를 취소합니다.
   - 열린 포지션은 기존 손절, 목표, 시간 제한대로 둡니다.
   - `shock_exempt` 알파(`liq_cascade`)는 예외입니다.
2. **국면별 켜짐 표 전환**: `regime_switch` 후보가 통과한 경우에만, 충격 국면의 표를 씁니다.
3. **킬 스위치 민감도**: 마지막 충격 감지 후 30일 동안 CUSUM 경보선 h를 8에서 6으로 낮춥니다. k와 최근 30건 합 기준은 그대로입니다.
4. **재검증 창**: 충격 상태가 시작된 때부터 마지막 감지 후 45일까지, 리서치 사이클 창을 120일에서 45일로 줄입니다. 리서치 제안 규칙과 챌린저 판정점·기준은 그대로입니다.

- **바뀌지 않는 것**: TRAIN·VALID·FORWARD 관문, 챌린저 판정점과 t 기준, 졸업 기준.
- 대응 1과 3은 진입을 줄이거나 끄기를 쉽게 하는 안전 방향입니다. 그래서 별도 관문 없이 기본으로 켭니다. 대응 2는 `regime_switch` 관문을 통과해야 켜집니다.
- F-pre-B 이후 lab 결과에는 대응 1과 S0가 들어갑니다. F-pre-B는 TRAIN-F의 충격 정시 수와 막힌 결정 수만 보고합니다(성과 수치 없음).

- 연구 도구는 봉인 블록과 겹치는 기간을 거부합니다. 대상: lab, discover, `backtest --start/--end`, 리플레이, 시간 단위·중립 평가기, 스크리닝 스크립트.
- 운영 봇의 자동 루프(리서치 사이클, 발굴, 챌린저, 킬 스위치)는 운영 DB로 계속 돕니다. 이 루프들은 사전 등록 판정을 내리지 않고, 그 결과는 확인 시험에 쓰지 않습니다.

**등록**
- 확인 시험은 `docs/results/forward_registrations.jsonl`(덧붙이기만)에 한 줄로 등록합니다.
- 담는 내용: 후보, 계열, 구성 해시, 코드 해시, 평가기와 정확한 명령, 관문, 블록 묶음, 등록 시각, 커밋
- 등록 시각은 묶음의 첫 블록이 시작되기 전이어야 합니다.
- 관문 담당이 감사를 마친 뒤 `heartless forward register`로 등록합니다. 운영 봇의 자동 경로(F3b)는 같은 명령을 코드로 부릅니다. 대상 블록은 시작까지 24시간 이상 남은 가장 이른 블록입니다.

**묶음 길이**
- 방향 계열: TRAIN의 30일당 거래 수로 계산한 기대 거래가 100건 이상이 되는 가장 작은 블록 수(1~3). 3블록으로도 모자라면 3입니다.
- 캐리·중립 계열: 3블록
- `ai_hypothesis`: 최소 2블록

**개봉**
- 블록이 끝나고 데이터가 완비되면 개봉합니다.
  - 완비: 확인에 필요한 구성원의 모든 1분봉(또는 1시간봉)과 모든 정산 펀딩이 있음
  - 출처: 아카이브(`universe build`의 월·일 파일 포함), 또는 운영 봇이 저장한 기록
- 확인 세션(`heartless forward confirm FWD-k`)이 하는 일:
  1. 그 블록에서 끝나는 등록을 모두 한 번씩 돌립니다(명목 + 스트레스).
  2. `docs/results/fwd_<블록>_<후보>.json`을 씁니다.
  3. 봉인 원장(`seal_ledger.jsonl`)에 개봉 한 줄을 남깁니다(돌린 등록 목록 포함).
  4. 블록을 소진(`SPENT`)으로 옮깁니다.
- 등록이 없는 블록도 같은 방식으로 빈 개봉을 기록합니다.

**여러 블록 묶음**
- 앞 블록은 일정대로 개봉되지만, 묶음 후보는 마지막 블록이 개봉될 때 한 번만 평가합니다.
- 등록이 열려 있는 구성 해시는 그 묶음과 겹치는 기간에서 평가할 수 없습니다(F4가 거부).

**그 밖의 규칙**
- 결과 없이 중단된 실행만 다시 돌릴 수 있습니다. 사유를 등록 원장에 남깁니다.
- FWD-01은 이 등록보다 먼저 시작되었으므로 등록할 수 없습니다. 완비되면 빈 개봉으로 소진됩니다. 첫 확인 가능 블록은 FWD-02(2026-11-06)입니다.
- 소진된 블록은 일반 이력입니다. TRAIN-F는 늘리지 않습니다. 늘리려면 새로 등록합니다.

### 7.10 가설 파이프라인 (F3)

**F3a `discovery_f`: 피처 집합 자동 확장**
- 발굴 엔진의 피처 집합에 버전을 붙입니다.
- 새 버전 = 기존 피처(F-pre-B의 `vwap_z` 첫 봉 수정 포함) + F5가 과거 데이터로 만들 수 있는 피처
  - 베이시스 z, 프리미엄 지수, 대용 청산 사건, 다음 펀딩 정산까지 남은 시간
  - 실시간으로만 쌓이는 피처(호가 불균형, `forceOrder`)는 6블록 이상 쌓이기 전까지 넣지 않습니다.
- 버전마다 발굴을 한 번 합니다. 버전은 한 달에 한 번까지입니다.
  - `discover --universe top40 --train 2022-01-13:2025-01-01 --valid 2025-01-01:2026-01-01 --grid 1h,1d --templates all --context --tag discovery_f`
  - 두 구간 모두 TRAIN-F 안입니다.
  - N = 탐색한 규칙 수이고, 버전을 거듭하면 합산합니다.
- 자체 검증을 통과한 규칙 중 최대 2개를 독립 알파 파일로 옮겨, lab으로 TRAIN 관문(TRAIN-F 전체, 방향 관문)을 봅니다.
- 확인은 VALID-F입니다. 규칙을 TRAIN에서만 채굴했기 때문입니다.
  - 예외: P2에서 VALID를 본 규칙과 피처·방향이 같고 임계값이 ±10% 안이면 FORWARD로 확인합니다.

**F3b `ai_hypothesis`: AI 연구자**
- `ANTHROPIC_API_KEY`가 있을 때만 돕니다. 소유자가 넣는 키는 Binance 키뿐이므로 기본은 꺼짐입니다.
- 주 1회까지 새 알파 하나를 제안합니다.
  - 입력: 이 절의 규칙, 알파 인터페이스, 원장 요약, 계열별 TRAIN 결과 요약
  - VALID·FORWARD 결과는 주지 않습니다.
- 제안 코드는 `<데이터 폴더>/proposals/`에 두고 샌드박스에서만 실행합니다.
  - 별도 프로세스, 네트워크 없음, 파일 쓰기 없음
  - 허용 모듈 목록(math, numpy, `heartless.strategy.base`, `heartless.data.features` 등)
  - CPU 30분, 메모리 1.5GB 한도
- 1분봉이 없는 동안에는 제안을 1시간 이상 결정 주기로 제한합니다.
- 처리 순서:
  1. 정적 검사
  2. import
  3. 불변식 검사: 심볼명 치환, 가격 ×1000/×0.001/×1024, 결정 봉에서 자른 뷰와 같은 결정
  4. 원장 기록
  5. TRAIN 관문(제안의 결정 주기에 맞는 평가기, 방향 관문)
  6. FORWARD 등록(최소 2블록)
- 불변식에서 떨어진 제안은 데이터로 평가하지 않았으므로 N에 넣지 않고, 별도 기록에만 남깁니다.
- 제안 하나의 구성은 최대 4개입니다. 계열 N은 모든 제안의 합입니다.
- **사람 없이는 넘지 않는 선**
  - FORWARD를 통과해도 출하 기본으로 켜지 않습니다.
  - 페이퍼 챌린저로만 설치합니다. OOS 탈락 알파와 같은 강화 판정점(30·60·90일)을 씁니다.
  - 텔레그램으로 한 번 알립니다. 소유자가 승인 버튼을 누르지 않으면 챌린저에서 멈춥니다. 챔피언 승격, 출하 기본, 실거래 모두 없습니다.
  - 소유자에게 질문하지 않습니다. 승인은 소유자가 원할 때 누르는 버튼입니다.

### 7.11 운영 규칙 (F0·F7)

**거래소 전체, 코인 하드코딩 금지**
- 운영 유니버스는 `universe.live_selection` 규칙을 통과한 종목 중 상위 `UNIVERSE_SIZE`입니다. 매 시간 다시 고릅니다.
  - 규칙: USDT 무기한, `TRADING`, 스테이블코인 제외, 상장 30일, 24h 거래대금, 틱 10bp, 호가 스프레드 5bp
- `ALWAYS_INCLUDE`(기본 `BTCUSDT`)는 레짐·컨텍스트 기준을 위한 데이터 구독일 뿐, 거래 보장이 아닙니다. F6 재배선에서 거래 목록과 분리합니다.
- 시장 컨텍스트
  - 연구 저장소는 `top_n = 40`으로 빌드합니다. 후보 집합은 그 구간 연구 유니버스의 구성원 전체입니다.
  - 운영은 F6 재배선 때 `CONTEXT_TOP_N = 40`으로 바꿉니다. 후보 집합은 운영 선택의 거래소 필터를 통과한 무기한 전체입니다. 고정 20종목 목록은 폐기합니다.
- 알파와 전략 코드는 심볼 이름을 읽지 않습니다. 새 알파는 불변식 테스트(이름 치환, 가격 배수)와 결정 봉 절단 테스트를 통과해야 원장에 기록할 수 있습니다.

**속도와 지연 예산** (F7 측정 기준. `/health`, 일일 보고, 리플레이 보고에 게시)

| 단계 | p50 목표 | p99 목표 |
|---|---|---|
| `feature_update` (종목당 1분봉) | < 1 ms | < 5 ms |
| `close_to_decision` | – | < 1,000 ms |
| `close_to_sent` | – | < 1,500 ms |
| `sent_to_ack` (실거래) | – | < 1,000 ms |
| 시작 환경 점검 | < 3 s | – |

- p99가 3일 연속 목표를 넘으면 일일 보고에 표시합니다. 설정은 자동으로 바꾸지 않습니다.
- `INCREMENTAL_FEATURES`는 켭니다(재앵커 자체 점검 유지).
- `ORDERBOOK_STREAM`은 `ctx.book`을 읽는 알파나 메이커 체결로 켜진 알파가 있을 때 켭니다.

**호가 이상 시 진입 보류** (백테스트와 운영이 같은 규칙, F-pre-B)
- 다음 중 하나면 진입을 건너뜁니다.
  - 스프레드가 그 종목의 직전 24시간 중앙값의 3배 이상이고, 5bp 이상
  - ±10bp 깊이가 직전 24시간 중앙값의 25% 미만
- 과거 데이터는 `bar_book_proxy` 대용치를 씁니다. 대용치는 실제보다 보수적입니다. 기준이 종목 자신의 평소 값 대비 비율이라, 대용치에서도 뜻이 같습니다.

**데이터 예산**
- 새 데이터는 1시간봉을 기본으로 하고 `universe.db`에 둡니다.
- 1분봉은 1분 결정 계열의 구성원 달(+ 워밍업)만 받습니다.

**순서**

```
Wave F-1  [F-pre-A 연구 도구]          ‖  [F-pre-B 엔진·충격·메이커 모드]
Wave F-2  [F4 FORWARD 봉인]            ‖  [F6 배포 + F5 전진 수집]
Wave F-3  [carry_neutral]              ‖  [pairs_neutral]                 (1시간 데이터, 지금 있음)
Wave F-4  [F-data-h → liq_cascade]     ‖  [event_funding (E2부터)]
Wave F-5  [관문 담당: TRAIN 재계산·감사 → VALID 한 번씩 → FORWARD 등록]
Wave F-6  [F-data-1m (디스크 조건) → maker_exec → discovery_f]  ‖  [F3b AI 파이프라인 구현 (키가 있을 때만 돎)]
Wave F-7  [regime_switch (TRAIN 통과 방향 후보 2개 이상일 때)]
상시      블록마다 FORWARD 확인 세션 (F4 도구) → 관문 담당이 판정 적용
```

- **초안 순서(F1 메이커 먼저)와 다른 이유**
  - 메이커 재평가에는 1분봉 약 9 ~ 12GB가 필요한데, 지금 디스크 여유는 1~2GB입니다. 그래서 데이터가 이미 있는 1시간 계열을 먼저 합니다.
  - FORWARD 봉인(F4)은 FORWARD로 확인할 후보가 나오기 전에 있어야 하므로 F-2로 당깁니다.
  - F6 배포는 실시간 데이터가 쌓이는 데 시간이 걸리므로 일찍 시작합니다.
- 동시 실행 에이전트는 최대 2개입니다. 같은 Wave의 두 작업은 담당 파일이 겹치지 않게 나눕니다. 각 Wave 끝에 전체 테스트, 검토, 커밋을 합니다.
- **계열 연구자의 산출물**
  - 계열 평가 코드(새 파일), 원장 줄, `docs/results/wf_<태그>_*.json`, `docs/RESEARCH_F.md`의 계열 절
  - 후보는 알파(또는 전략) 모듈로 옮겨 기본 비활성으로 커밋합니다.
- **관문 담당의 산출물**
  - `docs/results/wf_decisions.json`, 확인 결과 파일
  - 증거 기록 갱신과 `enabled_by_default` 변경
  - 이 문서 5절에 Wave F 행 추가

### 7.13 결정 원칙 (소유자에게 묻지 않도록 미리 정함)

- 어떤 계열도 관문을 넘지 못하면, 봇은 페이퍼에서 연구, 발굴, 챌린저만 계속합니다. 이것도 정상적인 결론입니다.
- 레버리지: 캐리·중립 계열은 2배 이하입니다. 방향 알파는 기존 위험 예산(거래당 0.5%)을 씁니다.
- 현물 권한: 키에 현물 거래와 범용 이체 권한이 있으면 자동 감지해, 통과한 캐리를 실거래 후보로 둡니다. 없으면 캐리는 페이퍼에만 두고 시작 메시지에 한 줄로 알립니다.
- 실거래 전환은 졸업 기준과 `/golive` 확인뿐입니다.
- 디스크나 데이터가 모자라면 그 계열을 기다리게 합니다. 다른 유니버스나 짧은 기간으로 대신하지 않습니다.
- **하지 않을 것**
  - 관문 낮추기, 결과를 본 뒤 기준 바꾸기
  - 봉인 블록을 본 뒤 등록하기
  - 고정 종목 목록으로 관문 판정하기
  - 1~5분 스캘핑 재시도(4절)
