# 전체 시스템 리플레이 soak 테스트 (P5)

`heartless replay`는 실제 `Heartless` 오케스트레이터(챔피언 페이퍼 엔진, 챌린저, 리스크 관리, 리서치 스케줄러, 텔레그램)를 저장된 이력 위에서 **가상 시계**로 돌리고, 매 가상 분마다 불변식을 검사합니다. 실시간보다 수백~수천 배 빠르고, 네트워크는 전혀 쓰지 않습니다.

```bash
HEARTLESS_DATA_DIR=<저장소 사본 폴더> ARCHIVE_BACKFILL=false \
  heartless replay --start 2026-07-01 --end 2026-08-30 --symbols BTCUSDT,ETHUSDT,... \
  --out runs/soak.json --messages-out runs/soak.messages.jsonl
```

- `--end`가 날짜만이면 그 날짜는 포함하지 않습니다(랩과 같은 규칙). 봉인 구간(2025)에 닿는 기간은 시드 이력까지 포함해 거부합니다. 원본 저장소는 이 검사를 통과한 구간(시드 시작 ~ `--end`) 밖의 데이터를 내주지 않습니다. 봇이 `HISTORY_DAYS`만큼 스스로 받아 오는 이력과 다음 정산을 보는 펀딩 추정치도 이 구간 안에서만 나옵니다.
- 리플레이용 봇은 새 데이터 폴더(`--work-dir`, 기본은 임시 폴더)에서 시작합니다. 시작 전 `--seed-days`(기본 60일)만큼의 1분봉·펀딩을 원본에서 복사해, 데이터를 모아 온 봇과 같은 상태로 만듭니다. 원본 DB는 읽기 전용으로만 엽니다. 원본이 들어 있는 폴더는 `--work-dir`로 쓸 수 없습니다(`--overwrite`가 폴더를 지웁니다).
- 결과: 요약 JSON(`--out`), 사람이 읽는 보고서(같은 이름의 `.txt`), 텔레그램 메시지 전체(`--messages-out`), 거래 목록(`--trades-out`). 위반이 하나라도 있으면 종료 코드 1입니다.
- 매 가상 1일마다 진행 상황 한 줄(`[replay] ...`)을 출력합니다.

## 동작 방식

- **가상 시간:** 앱의 asyncio 코루틴은 그대로 돌고, 이벤트 루프만 바뀝니다(`heartless/replay/clock.py`). 할 일이 없으면 다음 타이머 시각으로 바로 건너뜁니다. 스레드·프로세스 작업(봉별 피처 재계산, 리서치·발굴 워커)이 도는 동안에는 가상 시간이 멈춥니다. 그래서 결과가 기계 속도와 무관하고, 같은 입력이면 같은 결과가 나옵니다(밴딧 난수도 `seed`로 고정). `timeutil.now_ms()`는 리플레이 중에만 가상 시계를 따릅니다. 운영에서는 아무것도 바뀌지 않습니다.
- **리플레이 시장:** 공개 REST(klines, exchangeInfo, 24h 티커, 펀딩, 미결제약정·롱숏 지표)와 웹소켓(kline, bookTicker, markPrice)을 저장 이력으로 대신합니다(`market.py`). 1분봉마다 분 안의 네 시점(시가, 첫 극값, 둘째 극값, 종가; 양봉 O-L-H-C, 음봉 O-H-L-C)에 호가·마크가를 보내고, 종가 시각에 마감 kline을 보냅니다. 펀딩은 8시간마다 정산되고, 지표는 5분 버킷이 끝난 시각부터 보입니다. 그 시각에 존재하는 데이터만 응답합니다.
- **텔레그램:** 실제 `TelegramBot`이 돌고 HTTP만 캡처 스텁으로 바뀝니다(`telegram.py`). 모든 메시지를 가상 시각·이벤트 종류와 함께 기록합니다. `--command '+2d=/pause'`처럼 정한 시각에 소유자 명령을 보낼 수 있습니다(`/close *`는 그 시각에 열린 포지션, `@confirm`은 마지막 확인 버튼).
- **네트워크 차단:** 실제 HTTP·웹소켓·DNS 시도는 모두 예외를 내고 위반으로 기록됩니다(`netguard.py`).
- **학습 주기:** 리서치가 도는 동안 가상 시간이 멈추므로 기본 주기를 줄였습니다(리서치 7일마다, 후보 3개·폴드 2개·21일 창, 발굴 14일마다). `--set KEY=VALUE`로 바꿀 수 있습니다.

## 불변식 (`invariants.py`)

| 이름 | 내용 |
|---|---|
| positions | 엔진의 열린 포지션 = 계정 포지션(종목·방향·수량, 반 스텝 이내) |
| stops | 모든 열린 포지션에 보호 손절이 실제로 걸려 있음(방향·수량·가격 일치) |
| orphans | 모든 대기 주문·조건부 주문이 추적 중인 포지션이나 진입 주문에 속함, 종목당 손절 1개 |
| ledger | 잔고 변화 = 실현손익 - 수수료 + 펀딩(계정 자체 집계, 그리고 저장된 거래 + 열린 포지션 장부) |
| exceptions | 처리되지 않은 예외, ERROR 로그, 루프 교착이 없음 |
| pnl_reports | 일일 보고·`/pnl`·청산 메시지의 손익 = 그날 저장된 거래의 합(텔레그램 문구를 파싱해 비교) |
| memory | RSS를 가상 1시간마다 측정, 워밍업 이후 증가량과 기울기가 한도 안 |
| trades | 저장된 거래가 완전함, 최종 청산 뒤 열린 포지션·주문이 남지 않음 |
| network | 네트워크 접근 없음 |

## 한계

- 1분봉 안의 가격 경로는 네 점으로 근사합니다. 실제 틱 순서와 호가 깊이는 알 수 없습니다. 경로는 포지션과 무관하게 양봉 O-L-H-C, 음봉 O-H-L-C로 고정됩니다. 백테스터는 열린 포지션에 불리한 극값을 먼저 지나게 하므로, 한 봉 안에서 손절과 목표가에 모두 닿는 드문 경우 리플레이 성과가 백테스트보다 낙관적일 수 있습니다.
- 펀딩 `r`은 직전 정산값에서 다음 정산값으로 선형 보간합니다(저장 이력에는 확정값만 있음).
- 라이브 계정(`LiveAccount`) 경로와 웹 대시보드는 돌리지 않습니다.
- 봉마다 1분 피처 프레임(1,500봉 × 지표 60여 개)을 다시 계산하는 비용이 대부분입니다(봉당 약 35~50ms). 12종목 60일이면 몇 시간이 걸립니다.

리플레이가 찾아 고친 문제:

- 페이퍼 계정의 대기 주문 형식이 Binance와 달라(`kind` vs `orderType`) `reconcile()`이 손절을 못 알아보고 매번 새로 걸었습니다.
- 종목별 1분봉 메모리 배열이 끝없이 커졌습니다(하루 1회, 피처가 닿는 기간만 남기도록 정리. 피처는 비트 단위로 동일).
- 유니버스 경계 종목이 매시간 들락날락했습니다(2일 리플레이에서 AVAX 6회). 기존 종목은 기준의 80% 아래로 떨어질 때까지 유지합니다. 60일 동안 77회로 줄었습니다.
- 펀딩 정산이 시작할 때만 저장되어, 리서치 백테스트가 몇 주 동안 시작 시점 펀딩률을 적용했습니다. 매시간 새 정산을 저장합니다.
- 폴링한 포지셔닝 지표를 저장하지 않아 리서치가 `positioning`·`funding_fade`를 데이터 없이 평가했습니다. 저장합니다.
- 자정 직후 몇 초 안에 닫힌 거래가 전날 일일 카운터에 들어갔다가 지워졌습니다(청산 메시지의 "오늘 실현손익"). 틱·봉·수동 청산 전에 날짜를 넘깁니다.

검토에서 고친 문제:

- 매 분 불변식 검사를 도는 태스크는 아무도 기다리지 않아서, 검사 중 예외가 한 번 나면 태스크가 조용히 끝나고 남은 기간은 검사 없이 PASS가 나왔습니다. 이제 예외는 위반(`exceptions`)으로 기록하고 다음 분부터 계속 검사합니다.
- 폴링한 지표를 저장할 때 일부 시리즈만 답한 버킷(한 시리즈가 한 버킷 늦거나 빈 응답)이 행 전체를 덮어써, 앞선 폴링이 저장한 값이 지워졌습니다. 한 버킷씩 늦는 시리즈가 있으면 모든 버킷이 결국 그 시리즈 하나만 남았습니다. 이번 폴링에 없는 값은 저장된 값을 유지합니다.
- 리플레이 시장이 원본 저장소 전체를 내줬습니다. `HISTORY_DAYS`가 `--seed-days`보다 길면 봇이 봉인 구간(2025) 1분봉·펀딩을 받아 왔고, 2024년 말에 끝나는 구간에서는 마지막 몇 시간 동안 펀딩 추정치가 2025년 첫 정산값을 섞어 보여 줬습니다.
- 챌린저 퇴출 시 청산은 엔진이 목록에서 빠진 뒤에 일어나 매 분 검사가 닿지 않았습니다. 퇴출 직후 그 엔진의 포지션·손절·고아 주문·장부를 한 번 더 검사합니다.
- `--work-dir --overwrite`가 원본 저장소가 든 폴더(예: 데이터 폴더)를 가리키면 리플레이할 이력을 지웠습니다. 거부합니다.
- `--messages-out`·`--trades-out`의 폴더가 없으면 몇 시간짜리 실행이 끝난 뒤 쓰기에서 예외가 나 결과를 잃었습니다. 시작할 때 폴더를 만듭니다.
- 장부(ledger) 허용 오차가 0.01 USDT였습니다. 실제 오차는 60일 동안 1e-11 USDT 수준이라 작은 포지션의 펀딩 누락(약 0.001 USDT)을 놓칠 수 있었습니다. 초기 잔고 대비 1e-10(1만 USDT에서 1e-6 USDT)으로 줄였습니다.
